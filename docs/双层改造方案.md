## 1. 目标 / 非目标

**目标**：让「长期事实」（`category === 'stable_profile'`）跨工作区、跨会话共享；「事件」（`event`）仍留在各自会话里，不串味。

**非目标**：
- 不做全量全局（事件不共享）
- 不改淡忘 / 证据召回 / 缩放算法
- 不改 UI 交互，只在设置页多显示一行「全局事实 N 条」

**理由**（数据支撑）：本机主会话库 525 条记忆里 `stable_profile` 202 条、`event` 323 条。真正需要跨工作区的「我是谁 / 偏好 / 约定」几乎全在 facts 层；事件跨工作区反而会污染（IM 群聊的事流进代码工作区）。

## 2. 现状（1.3.7 代码事实）

| 位置 | 内容 |
|---|---|
| `lib/index.js:225` | `storePath(sid)` = `<DSH_HOME>/clay-memory/<sid>.json` —— 一会话一文件，这是唯一需要动的地基 |
| `lib/index.js:260` | `loadStore(sid)` 读单文件，坏 JSON 有隔离/自愈逻辑（`corruptIncidents`、`corruptSnapshots`） |
| `lib/index.js:398` | `saveStore(sid,data,选项)`：**全程同步**、写前读盘 `合并库`、`writeFileAtomicSync` 原子写、`memSig` 变化才备份 |
| `lib/index.js:362` | `backupStore(sid)` / `338` `销毁前另存(sid)` |
| `lib/index.js:2912` | 常驻事实层：从 `memories` 里 filter `stable_profile`，按「重要度 → createdAt」取前 `factsMax` 条，每轮必带 |
| `lib/index.js:6054` | 已有 `/dsh-clay-memory/copy-to`（整库复制到别的会话） |
| `lib/index.js:3900` | 已有「分支继承」（fork 会话自动继承母会话记忆） |
| `lib/index.js:2392` | 「她自己怎么说话」的尺子是**内存态**（`拿尺(sid)`），不落盘 → 改造不受影响 |

**关键结论**：所有上层逻辑都只通过 `loadStore` / `saveStore` 两个入口碰存储。把这两个函数改成「双层合并 / 拆分写入」，上层（召回、注入、删除、导入、设置页）基本零改动。而且 `saveStore` 是同步函数，Node 单线程内不会交错读写，**同进程多会话并发写全局库是安全的**。

## 3. 设计

### 3.1 存储布局

```
<DSH_HOME>/clay-memory/
  _facts.json              ← 新增：全局事实库（所有工作区 / 会话共享）
  <sid>.json               ← 保留：会话库（事件 + traces + deleted + policy）
  <sid>.json.bak-*         ← 原样
  _facts.json.bak-*        ← 新增
```

### 3.2 读写规则

```
loadStore(sid):
  facts = 读 _facts.json          （不存在 → blank()）
  own   = 读 <sid>.json           （不存在 → blank()）
  return {
    ...blank(),
    policy: own.policy,           // 库级参数仍归会话
    traces: own.traces,           // 召回历史属会话
    purgeEpoch: own.purgeEpoch,   // 代际按会话
    deleted: [...own.deleted, ...facts.deleted],   // 删除墓碑两边都认
    memories: [...facts.memories, ...own.memories],// 事实在前，事件在后
  }

saveStore(sid, data, 选项):
  facts部分 = data.memories.filter(m => m.category === 'stable_profile')
  own部分   = data.memories.filter(m => m.category !== 'stable_profile')
  → 两份各自：读盘 → 合并库(盘, 本份) → 校验 purgeEpoch → 原子写
  traces / deleted / policy 只写会话库
  （删墓碑按 id 归属拆：被删的是事实 → 进 _facts.deleted；事件 → 进会话 deleted）
```

### 3.3 影响面确认

| 行为 | 改造后 |
|---|---|
| `remember` 工具写一条 `stable_profile` | 进 `_facts.json` → 所有会话立刻可见（下一轮注入） |
| `remember` 写一条 `event` | 进当前会话库，不跨会话 |
| 每轮注入 | 常驻事实从 `_facts.json` 里取前 `factsMax` 条（**自动生效，不用改代码**） |
| 会话开关 `isEnabled(sid)` 关 | 事件与事实都不注入（保持原语义：这间不想用记忆） |
| 删除一条事实 | 全局生效（预期行为，设置页要提示「这是全局事实，删了所有会话都会忘」） |
| `/import/apply` 导入 | 按 `category` 自动分流（导入的事实进全局库） |
| `/import/undo`、`/delete`、`/edit`、`/duplicates` | 走 loadStore/saveStore，自动适配；只需确认删除墓碑的归属 |
| `copy-to` / 分支继承 | 事实已经全局，无需再复制；改为只拷事件、并提示「事实是全局的」 |
| 设置页 stats | 增加「全局事实库 N 条」一行；本会话条数改为只统计事件 |
| `factsMax` 默认 2 | **建议调大**：全局事实层 202 条时取前 2 条意义有限；默认改 `factsMax: 6`，或按 `tags` 过滤工作区 |

### 3.4 「事实带作用域」（可选增强，第二阶段）

给事实加可选字段 `scope: 'global' | ['IM', '需求开发']`，注入时按当前工作区过滤。默认 `global`。
第一版不做，只在数据结构上预留（不写字段 = 全局）。

### 3.5 迁移（一次性、幂等、可回退）

```
migrate-facts.mjs（随插件带 tools 脚本，也可手动跑）：
  1. 备份整个 clay-memory/ → clay-memory-backup/<时间戳>/
  2. 遍历 <sid>.json：
       取出 category === 'stable_profile' 的记忆
       按 (归一化 text) 去重后并入 _facts.json（保留原 id；冲突按 updatedAt 新者胜）
  3. 默认 **不删原库里的副本**（回退旧版本时记忆还在）；加 --purge 才删
  4. 写 _facts.json 的 migration 标记 { from: [sid...], at }，二次运行直接跳过
  5. 输出报告：新增 N 条 / 去重 M 条 / 跳过会话 K 个
```

**回退**：旧版本不认 `_facts.json`，回退后事实「消失」——但因为默认不删原库副本，回退旧版本看到的仍是迁移前的状态。恢复原状 = 还原整个目录备份。

## 5. 风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| 多实例同 DSH_HOME | 两个 DSH 进程同时写 `_facts.json` → 丢失更新 | 测试实例必须用**独立 DSH_HOME**（本次即 `G:\tmp\home\.dsh`）；生产建议单实例 |
| 删除事实影响全局 | 用户在会话 A 删一条事实，会话 B 也忘 | 设置页删除确认改成「这是全局事实」，可加二次确认 |
| 旧版本回退 | 旧版读不到 `_facts.json` | 迁移默认不删原库副本；整目录备份 |
| 事件污染事实 | 模型把「今天聊了 X」记成 `stable_profile` | 迁移与 remember 时校验 category 白名单；设置页可改分类 |
| `_facts.json` 变大 | 事实只增不减（不淡忘） | 事实层本来就该少而稳；加「超过 500 条提示清理」 |

### 用例

1. **跨会话事实**：会话 A 说「记住我喜欢 X」→ 新开会话 B（同工作区）→ 问一句 → B 的注入里出现这条事实。
2. **跨工作区事实**：把测试实例工作区切到 `G:\tmp\workspace\sub` → 事实仍注入。
3. **事件不跨会话**：A 里记一条事件 → B 不应看到。
4. **常驻层**：`factsMax=2` 时只带前 2 条；改 6 后带 6 条。
5. **删除全局生效**：A 删一条事实 → B 刷新后不再注入，`_facts.json.deleted` 留墓碑。
6. **迁移幂等**：跑两遍 `migrate-facts.mjs`，第二遍 0 新增。
7. **回退**：还原目录备份 → 旧版本能正常读，事实仍在。
8. **并发**：同一实例开两个会话同时 remember → `_facts.json` 两条都在（同步写不交错）。
9. **中文/人称**：事实里「主人」在别的会话仍按当前会话 selfName 渲染。
