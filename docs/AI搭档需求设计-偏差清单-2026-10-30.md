## 1. 偏差清单（3 处实质偏差）

### A. 工作区上下文层（§3.2 / §4 `workspace:<id>`）—— ✅ 已修（1.8.37）

- 需求：项目目标、技术栈、架构约束、任务进度、决策、待办，默认仅限所属工作区，作用域建议 `workspace:<id>`。
- DSH 实际结构：**工作区（cwd）1:N 会话**，打开 DSH 可有多个工作区；同一工作区下开新会话 = 新 session_id。
- 现状：插件里「工作区」只存在于展示层——`workspaceRegistry`（`lib/index.js:4166` 拿工作区列表、
  :6584 `/workspaces`、:6602 `/sessions-by-workspace` 选档案用）、`process.cwd()`（:4148 当前工作区根）。
  **记忆存储没有工作区维度**：`scope` 只有 `global` / `session` 两个值（映射 `lib/storage.js:158`；
  赋值 `lib/index.js:5412` `scope: 归哪 === 'stable_profile' ? 'global' : 'session'`，:4090/:4356/:5105/:6490 同款；
  :5372 校验文案「scope 只认 global（全局记忆）或 session（指定会话）」）。
- 后果（两个方向都不对）：
  1. **过严**：同一工作区下不同会话的项目记忆不共享——项目进度落在 session 里，开新会话就只剩 event 召回
     （P3 实测事件层平均 0.79 条/句）；
  2. **过松不存在**：项目私有信息不跨工作区泄漏反而天然满足（session 属于工作区），这是 session 隔离兜住的。
- 建议：加中间层 `workspace:<cwd>`（或复用 session 文件按 cwd 归组）。**只放项目事实/进度/决策，不放事件**
  ——`lib/index.js:243` 已记录「事件跨工作区反而会串味（IM 群聊里的事流进代码工作区）」，事件仍按 session 存。
  落地顺序：先给 `type` 加 `progress`/`decision` 两个值把项目类记忆标出来，再决定 scope 枚举与镜像列语义，
  避免一次改两层。

### B. 「推测与解释」内部候选类型缺失（§4 第 7 行 / §5 写入规则）—— ✅ 已修（1.8.36）

- 需求：对动机/性格的推断不得当确定事实，必须标注推测并携带证据，**默认不注入**。
- 现状：`type` 只有 6 类（identity/relationship/agreement/preference/experience/misc，
  `lib/index.js:5566` 一带映射），无「推测」；importance 分档只区分「长期/某天发生的」，无推测语义。
  推断目前和普通记忆同权，靠 refine 的措辞约束（`lib/index.js:2152` 一带）软挡。
- 影响：模型把「用户可能是 XX 型」写成普通记忆后会被正常召回——与需求「默认不注入」不符。
- 建议：加 `type=inference`；写入侧要求带 `evidence` 字段、默认 `importance <= 0.4`；
  recall 侧对 inference 类默认过滤（或只在被显式问起时召回）。

### C. 对外接口层（§6）未实现（当前豁免）

- 需求：`recall / propose / apply / patch / suppress / delete / trace`，且「上层不得直接修改底层 JSON/SQLite」。
- 现状：插件内函数级接口 + 设置页 HTTP 路由；没有版本化的 propose/apply 契约。当前无上层消费者
  （DSH 直接 import 插件），文档自身也给了「若接口不同，先写适配器」的余地——**现阶段豁免**。
- 触发条件：鱼塘/自主行动接线前必须先有适配器，届时 `store-merge.mjs` 的合并语义要一并暴露（幂等/冲突口径）。
