## 陈旧检查：记忆里提到的路径还在不在（1.12.74 起，**1.12.79 起默认不启用**）

记忆里写了「某个东西在 `X:\...`」，那个东西后来被搬走、删掉、换盘了，记忆本身不会知道。这个检查每 24 小时扫一遍所有活跃记忆，把**盘符路径**抠出来，用 `fs.existsSync` 判断还在不在，**不吃模型、也不判断这条记忆对不对**。

- **只看路径**。版本号、日期、命令、URL 一律不碰。
- 判断口径是**盘符根**：盘根不在（移动硬盘没插）→ 判不了，不报；盘根在 + 路径不在 → 疑似过时。
- 结果落在 `<DSH_HOME>/clay-memory/_stale.json`。开回来之后，去 **设置 →「黏土记忆」→「体检」→「陈旧检查」** 折叠区看（现在折叠区也一起藏起来了）。
- 每条路径一行，能看到哪几条记忆提到它；同一个句子里还有别的有效路径会标绿「同一句里还有有效路径」，像在说「以前那台机器」会标黄「像在说以前的事」。
- 两个按钮：**标成过时（不再召回）**（把那几条记忆标成已被取代，被谁 = 陈旧检查）/ **留着，别管它**（加进忽略名单，以后不再提醒）。已经标过的还能在「已标成过时的」那一列点**撤销**（1.12.75 起）。
- 路径又出现了（移动硬盘插回来）→ 自动标「已恢复」，不再重复报。

想立刻扫一次：开回来之后点折叠区里的「现在扫一次」，或 `POST /dsh-clay-memory/stale/scan`（路由要开回来才注册）。开回来的开关在 `lib/index.js`：`export const 启用陈旧检查 = false   // ← 改成 true，然后重启桌面`。

> 它只是**提示**，不是判决。路径不存在不等于记忆错了 —— 那条记忆可能在讲「以前在哪」，也可能当年就没装成。**点按钮的永远是人**。

## 工具拦截：别碰某些东西（**1.12.79 起默认关闭，设置页里的页签也撤了**）

> **这一节讲的是「已经关掉」的功能。** 代码和测试都还在（约 1600 行），想用回来改一个常量就行，见下面「怎么开回来」。
> 1.12.79 瘦身时的判断：它属于权限域的活，跟「记忆」不是一件事，默认关着、需要的人自己开。

记忆插件本来只管「记」和「想起来」。这一节管的是另一边：**在助手真正动手之前把它拦下来**。

它挂在 DSH 的 `ctx.tools.guard()` 上——每次工具调用（读文件、写文件、跑命令……）dispatch 之前过一遍，
命中规则就返回拒绝理由，调用**根本不执行**。注意它和「在提示词里写一句『别动那个目录』」不是一回事：
提示词靠模型自觉，这个是真拦住。

**规则由你自己写**，插件里一条都不内置。

> **Beta —— 这是一道「提醒」，不是「保险箱」。**
> 它只按「工具名 + 参数正则」去比。写法不对、路径换个写法（比如 `/c/Windows`）、或者本机工具名跟规则里写的不一样（比如这台机器跑命令的工具叫 `pwsh` / `ops_bash`，不叫 `bash`），都可能漏；漏掉的时候工具会照常执行，它不知道。
> 要紧的东西别只指望它 —— 要真兜底，把会话的文件权限收紧（沙箱 / 审批），那道才拦得住「不该写的目录」。

### 怎么开回来

代码和测试原样留着（约 1600 行），改一个常量就回来：

```js
// lib/index.js
export const 启用工具拦截 = false   // ← 改成 true，然后重启桌面
```

（这是**启动时挂载**的入口开关，跟下面「配置改完不用重启」不是一回事。）

开回来之后，那个页签上能做的事：

- 开关总闸、增删规则、直接改每一列的 `id / tools / args / workspace / reason`
- **试拦一次**：填个工具名、参数 JSON、工作区，点一下就知道「这条规则到底拦不拦得住」——写正则再也不用心算转义
- 工作区下拉框的候选项是从你本机的会话记录里扫出来的，不用手打路径

保存即生效（配置按修改时间现读，不用重启）。写坏的规则整批拒收并逐条提示哪里不对，不会存半截进去。

### 用一句话说（1.12.72 起，页签撤掉后跟着一起藏起来了）

开回来之后，页签最上面那个框，写人话就行，比如「别让助手读 Windows 和 Program Files 里的文件」，点「翻成规则」，
插件会调自己的模型把它翻成上面那种 JSON 草稿。

**翻出来不会直接生效**：得你看过、点「并入规则表」、再点「保存」。翻歪了就当没翻，删掉就行。

几句话先说清：

- 翻译要花 token（一次一点，走你配置的模型），所以别拿它当聊天框
- 它只能表达「**拦什么**」；「除了某处以外都放行」这种还翻不出来，遇到这种话模型会改成拦你点名的危险位置
- 执行层不吃自然语言：`ctx.tools.guard()` 是同步热路径，每次工具调用都当场判一次，规则必须是编译好的 JSON/正则
- 翻完拿不准，照旧点「试拦一次」干跑一遍

配置文件的路径还是下面这个，页面改的就是它；想手改也随时可以。

```
<DSH_HOME>\clay-memory-config.json
```

```json
{
  "toolGuard": {
    "enabled": true,
    "rules": [
      {
        "id": "别碰系统目录",
        "tools": ["read", "write", "edit", "bash*"],
        "args": { "file_path": ["^[A-Za-z]:[\\\\/]Windows[\\\\/]"] },
        "action": "deny",
        "reason": "Windows 系统目录不归助手管"
      }
    ]
  }
}
```

| 字段 | 意思 |
|---|---|
| `enabled` | 总开关。**默认 false**，写了规则也要先打开 |
| `rules[].id` | 随便起，日志里靠它认人（不写就是「规则N」） |
| `rules[].tools` | 工具名数组。`*` = 全部工具，`bash*` = 所有 bash 开头的，不写 `*` 就是精确匹配 |
| `rules[].args` | 可选。`参数名 → 正则（字符串或数组）`。**数组内 OR，多个键 AND**；参数没给 = 不算命中（宁可不拦，也不乱拦） |
| `rules[].workspace` | 可选（1.12.70 起）。只在某个工作区里生效：写会话的工作区根（如 `<WORKSPACE>/需求开发`），`前缀*` 通配，数组任一命中，`*` 或不写 = 所有工作区。**比的是会话的工作区根，不是文件路径**。查不到会话工作区时这条不拦（宁可少拦，也不误拦） |
| `rules[].action` | 目前只支持 `deny`（拒绝）。`ask`（问一句再决定）要等以后接 `tools/pre-execute` |
| `rules[].reason` | 给模型看的拒绝理由，写清楚该怎么做比只写「不行」有用 |

几条容易踩的：

- **改完不用重启**：每轮从配置文件现读（按修改时间判断），存盘就生效
- **写坏的规则只跳过它自己**，别的规则照常工作，日志里会记一句「有 N 条规则写法不对」
- **防死循环**：同一个「工具名 + 参数」被拒到第 3 次，理由里会多一句「换个做法，原样重试还会被拦」——模型被拒后原样重试是常见病，让它知道自己原地打转
- **路径正则别手算转义**：正则在 JSON 里要过两层——JSON 自己吃掉一层（`\\` → `\`），正则里再要一个反斜杠得写 `\\`，所以「反斜杠或正斜杠」这个字符类在 JSON 文本里得写成 **四个反斜杠** `[\\\\/]`（上面示例里那串就是）。只写两个就变成 `[\/]`，那是「只匹配正斜杠」，Windows 路径**根本拦不住**——这个坑现场踩过一次。拿不准就别跟反斜杠较劲，直接点「试拦一次」验证
- **拿不准就跑干跑**：开回来之后用页签上的「试拦一次」填工具名 + 参数，直接看拦不拦得住，不用心算转义（没开页面时也能验：`node -e` 里直接调 `lib/guard.mjs` 的 `取规则` + `找命中`）。不想跟分隔符较劲，也可以干脆用 `.*` 或 `clay-memory.*_facts` 这种不带分隔符的写法绕过
- 它不管权限、不管沙箱（那是 DSH 自己的事），只管「该不该碰」
