# 🐋 黏土记忆 · Clay Memory

**给 DSH 里的会话一份会淡忘的长期记忆 —— 每条都带时间。**

聊得越久，上下文越挤。压缩一次，前面的事就淡了。
这个插件替它记着：**该记的记下来，想起来的时候自己会想起来，不重要的事慢慢淡掉。**

---

## 它做什么

| | 说明 |
|---|---|
| **会淡忘** | 每条记忆有「鲜活度」，越久越淡。半衰期默认 30 天 —— 不删，只是越来越难被想起来 |
| **自己挑重点** | 不是每句话都记。它按轮次判断哪句值得留下，每天还有配额，防止把上下文塞满 |
| **想起来靠证据** | 你问什么，它按「命中的词够不够特别」找，再按鲜活度、重要度、情绪排序，最多注入几条。分词用的是一份通用中文词表，所以「车」不会撞进「车站」里 |
| **要记一辈子的不淡** | 画像、喜好、约定这种标成「长期事实」（`stable_profile`），平着放着，不会过期 |
| **事实不淡，但不硬塞**（1.10.0 改） | 「事实不淡」是**类别**（记什么），「每轮都在」交给**骨架层**。事实池只带这句话**真有证据**的（相关度 > 0，最多 6 条，设置页能改 0~6），所以「早上好」这种无关问句不会被喜好和经历塞满；「我叫什么」这类每轮都得在的，放进 `_core.json` 骨架（见「骨架层」） |
| **带时间** | 每条都记着「这是什么时候的事」。跨年了会写「去年 09-17」 |
| **用上了就更难忘**（1.10.3 起） | 光被算出来不算，真被注入到对话里的那些，下次写盘时鲜活度悄悄抬一点（`新 = 鲜 + 0.2 × (1 - 鲜)`），越用越牢 |
| **记得住，也说得清**（1.10.4 起） | 记东西的时候如果库里已经有一条「有点像」的（相似度 0.5~0.85），它当场就会看见，并被告知是哪一条、可以用 `取代` 把那两条并成一件；完全一样（≥0.85）的自动合并，不重复记 |
| **自己也看得见毛病**（1.10.5 起） | 体检页是画给你看的，它自己在对话里看不见。所以改成：人家在问却没想起来、这轮塞满条数上限、记忆块快吃满字数预算 —— 这三种情况才在注入末尾挂一句 60 字以内的自检；一切正常时一个字都不多说 |
| **说的话有性质**（1.11.0 起） | 每条记忆能带 `性质`：事实 / 事件 / 梦 / 虚构 / 假设 / 过程。规则认得出「梦见」「假如」「编一个」这种，认出来就按那个性质存；认不出就留空、标 `uncertain`，**不硬塞成事实**。注入时会自报「（梦）」「（虚构）」，不会被当成真事讲 |
| **留着当时那句原话**（1.11.0 起） | 梦、假设、发生的事会连你当时那句原话一起存（60 字以内，敏感内容不存）；事实和事件不存 —— 免得「钥匙扔鞋柜上了」被当成经历，之后「拿到桌上了」反而覆盖不掉。结构化召回一条都没找到时，才会翻出原话兜底，并老实说明「这是原话，不一定就是答案」 |
| **漏网的先放候选区**（1.11.0 起） | 这一轮它没主动记、但话里出现了承诺 / 偏好 / 身份 / 梦·虚构·假设·耗时 这类线索，就把那句丢进候选区（`_candidates.json`，不进召回、不占额度）。设置页「记忆」页签能看到「候选 N 条」，逐条「记下」或「不管」—— 只标不放进去，免得把「今天不想聊这个」也记成事 |
| **骨架也归主库管**（1.12.0 起） | `_core.json` 那份每轮都在的骨架，原来是手写的、跟记忆库脱节。现在能跟主库比一比：主库里够格的（事实层 + 重要度 ≥ 0.8）该加哪几条、骨架里哪几条主库已经不认了。**只算差在哪，写回要你点按钮** —— 自动覆盖会把手写的风格、边界冲掉，冲掉没后悔药 |
| **攒够了才整理**（1.12.0 起） | 延迟整理有个硬闸门：距上次 **≥ 24 小时**、手上 **≥ 10 句**没归档的话，才动一次。动的时候不调模型 —— 把那些话过一遍线索规则，命中的先丢候选区；够不着就不动，也不推进时间点（否则永远攒不满） |
| **能导入旧档案** | 以前写过的 markdown / 纯文本档案，扫一遍出候选，你挑完它再改写成记忆 |
| **全都看得见** | 记了什么、哪条被想起来了、为什么没被想起来、删掉的都还在 |

## 需要什么

- **DSH**（DeepSeek Harness），带 Web 界面
- **一个能用的模型** —— 它借用你 DSH 里正在用的那个，**不用另外配 key、不额外花钱**

> 「提炼」「扩词」「重判」「补标」这些批量步骤会调用模型（走你现有的）。不点它们就不会调用。

## 适配哪个 DSH 版本（不用操心）

这个插件**跟着 DSH 一起更新**：作者这边跑的就是最新版的 DSH，**最新版插件永远是给最新版 DSH 写的**。

所以看到「不适配 / 不支持」之类的提示，基本都是**装到了旧版本** —— 升级到最新版、重启一次 DSH 就好。
真遇到新版对不上（比如 DSH 刚升级、插件还没跟上），提个 issue，作者会跟着改。

当前实测对照：插件 **1.12.81** ↔ DSH **最新版**（2026-11-22）

## 装法

在 DSH 里：**设置 → 插件 → 安装**，填下面这一行；或者命令行：

```
github:TunerRed/dsh-clay-memory
```

```sh
dsh plugin --profile web add github:TunerRed/dsh-clay-memory
```

（`--profile` 照你平时那个写：网页端一般 `web`，桌面端一般 `desktop`。）

装完**重启一次 DSH**。

重启后，打开 **设置 → 黏土记忆**。

> 还没上 npm，所以**要用上面那条 GitHub 的**。
> （以后要是上了 npm，`dsh plugin add dsh-clay-memory` 也能用。）
> ⭐ 最省事的一条：把仓库链接贴给你自己的 DSH，说「**帮我装这个插件**」。

## 装完先做什么（5 分钟，不用配）

**一、什么都不用配。** 装上就开始记了：聊天时它自己在后台挑值得留的话写进库。想让它记什么，直接说「记住：我下周三去北京」；它没主动记、但看着像承诺/偏好/日期的，会先掉进「候选区」，你在设置里点「记下」才进库。

> 它是**代码每轮扫一遍**，不是靠模型「想着」记 —— 所以说过的话基本不漏，但「今天吃了什么」这类琐事会被有意跳过。

**二、知道它在哪。** 设置 → **黏土记忆**，六个页签：

| 页签 | 管什么 |
| --- | --- |
| 记忆 | 记了什么；点正文能改，点 × 能删（删的还在回收站） |
| 时间线 | 按天看：那天记了什么、又想起过什么 |
| 会话 | 每个会话的开关、称呼、导入、提炼 |
| 回收站 | 删掉的都在，能找回 |
| 体检 | 我的回复里有多少「AI 味」句式（只观察，不拦） |
| 高级 | 参数、清空、骨架预览、从档案导入 |

**三、三件值得顺手做的（可选）。**

1. **搬旧账**：高级 → 从档案导入，选以前的日记/笔记/聊天导出，它扫出候选，你挑完再「提炼」。唯一要花时间的一步。
2. **看一眼骨架**：高级 → 骨架预览，看主库里够格的条目该往「每轮都在」的 `_core.json` 加哪几条。**只算差在哪，写回要你点按钮**。
3. **不让它记**：直接说「这条别记」，或者用 `suppress` 把某条永久压掉。

### 会花钱的地方（只有这几处）

日常的「记」和「想起来」**不调模型、不花钱**。下面这些批量步骤会走你 DSH 里正在用的模型、按量计费，**不点就不会跑**：

- 会话页的 **提炼 / 扩词 / 重判 / 补标**（把旧档案改写成记忆）
- 会话详情里的 **洗键**（给大量记忆补「这件事叫什么」）
- 高级页的 **生成档案**（把一个会话读完导出成九章档案）

这些按钮旁都标着「会调模型」，拿不准就先看条数/字数再决定。

### 数据在哪、怎么备份

都在 DSH 家目录（`%USERPROFILE%\.dsh\`，或你设的 `DSH_HOME`）：

```
.dsh\clay-memory-config.json      设置（只有一份）
.dsh\clay-memory\                 全部记忆（分三层文件，见「分层记忆」）
.dsh\clay-memory\clay-memory.db   SQLite 镜像，删了会从 JSON 重建
```

备份两种都行：记忆页右上角**「导出全部记忆（JSON）」**，或整个复制 `.dsh\clay-memory\`（最好先退出 DSH）。

### 让 AI 帮你装时，把这句转给它

- **桌面端不能用 `dsh plugin` 命令**（报 `managed exclusively by the Electron application`）：要么在界面里装，要么改 `profiles\desktop\package.json`（加依赖 + `dsh.profile.bundles` 加一行）+ 在 `node_modules` 里建链接。
- **更新必须先卸再装**，否则可能拿到缓存旧副本；卸载不删设置和记忆。
- **改 profile 里的文件一律存 UTF-8 无 BOM**：Windows 的 `Set-Content -Encoding UTF8` / `Out-File -Encoding utf8` 默认带 BOM，DSH 读到会起不来。
- **装完重启一次 DSH**；**别用「重装 DSH」来更新插件**。

### 装完起不来？先看这个

如果 DSH 弹「The application could not start」，错误里有 `Unexpected token '﻿'`、`is not valid JSON`、
`readProfileManifest` —— 那是 profile 的 `package.json` 被存成了 **UTF-8 带 BOM**。
**跟插件无关**：内容都是对的，只是开头多了三个看不见的字节，DSH 读它就崩。

**先找出来**（不同装法位置不一样，别猜 —— 真正的 profile 目录里同时有 `cordis.yml`、`cordis.patch.yml`、`package.json`；机器上别处那些同名的都不算）：

```powershell
Get-ChildItem C:\,D:\,E:\ -Directory -Filter profiles -Recurse -Depth 4 -ErrorAction SilentlyContinue |
  ForEach-Object {
    Get-ChildItem $_.FullName -Directory -ErrorAction SilentlyContinue | ForEach-Object {
      $p = Join-Path $_.FullName 'package.json'
      if ((Test-Path (Join-Path $_.FullName 'cordis.patch.yml')) -and (Test-Path $p)) {
        $b = [System.IO.File]::ReadAllBytes($p)
        $bom = ($b.Length -ge 3 -and $b[0] -eq 0xEF -and $b[1] -eq 0xBB -and $b[2] -eq 0xBF)
        "{0}   BOM={1}" -f $p, $bom
      }
    }
  }
```

**输出里 `BOM=True` 的那一行，就是要修的文件**（标准安装在 `C:\Users\<你>\.dsh\profiles\<档名>\package.json`）。
去掉 BOM（路径换成上面那一行）：

```powershell
$p = "把上面 BOM=True 那一行的路径粘到这里"
[System.IO.File]::WriteAllText($p, [System.IO.File]::ReadAllText($p), (New-Object System.Text.UTF8Encoding($false)))
```

然后重启 DSH 就好，**数据一点没丢**。实在进不去时，那个错误框里的
**「Disable third-party plugins, back up profile patch, and restart」** 能先起来，再一个个开回去定位。

> ⚠️ 手动改 profile 里的文件，一律存 **UTF-8 无 BOM**。让 AI 帮你改时，别让它用
> `Set-Content -Encoding UTF8` 或 `Out-File -Encoding utf8`（Windows 自带的这两个默认**带 BOM**）。

## 更新到最新版

**最省事**：把这个仓库的地址丢给你自己的 DSH，说「**帮我更新这个插件**」。装完**重启一次 DSH**。

也可以点 **设置 → 黏土记忆 最上面的「检查更新」** —— 有新版会提示，还能一键复制更新命令。

命令行（`--profile` 照你平时那个写，桌面端一般 `desktop`、网页端 `web`）：

```bash
dsh plugin --profile desktop remove dsh-clay-memory
dsh plugin --profile desktop add github:TunerRed/dsh-clay-memory
```

> ⚠️ **必须先卸再装**：直接装可能拿到缓存里的旧副本，装完还是老的。
> ⚠️ 装完**重启一次 DSH**才会用新代码。

### 我的设置会不会丢？

**不会。** 设置存在 DSH 家目录（`%USERPROFILE%\.dsh\`）里，不在插件代码里；卸载只删代码：

```
.dsh\clay-memory-config.json   （设置，只有一份）
.dsh\clay-memory\              （全部记忆，分三层文件，见「分层记忆」）
```

所以卸载 → 重装，设置、记下来的所有记忆 都还在。

三件小事提醒：

- **别用「重装 DSH」来更新插件** —— 那是两件事，重装可能动到 profile。
- **新版本新加的设置项**会用默认值（以前没这一项），想要自己的值就再填一次。
- 设置项改名或换单位时，旧值会按规则自动换算，不用你管。

## 怎么用

### 第一步：直接聊就行

**装好就是开着的**，哪个会话都能记、也能读，不用先点开关。

哪个会话不想用记忆（比如写代码那间），到「黏土记忆」设置里的「▸会话」展开、把它单独关掉；
整个功能都不想要，关掉「remember 工具」。

### 第二步：正常聊

开着之后，它自己会判断该记什么。你不用管。

**记的时候有两条线**：

- 一天最多记几条（默认 10 条）—— 防止它把鸡毛蒜皮都记下来
- 一次最多注入几条（默认 6 条）—— 防止占太多上下文

### 第三步：想知道它记了什么

设置里点「黏土记忆」，**一张列表就是全部记忆**，不用先挑会话：

- 顶上状态条：今天记了 N 条 · 想起 M 次
- 下面一行小字（1.10.3 起）：近 7 天注入了多少次、几次真有着落、平均几条几个字、几次空注入（其中几次被问句门挡）
- 每条右边有徽章：**所有会话**（所有对话都看得见）或 **只在这个会话 · xxxxxxxx**
- 点正文就能改；点 × 删（会先问一句「所有会话都会忘，真删？」）
- 搜框能搜正文 / 检索词 / 出处 / 「讲的是」
- 有「**你说的**」徽章的（1.10.3 起），展开能看到记这条时你最近说的那句话
- 三行筛选：作用域 · 类型 · 状态（活跃 / 已被取代 / 已删）

想手动记一条：点「**＋ 记一条**」，写正文、选个类型、给个重要度 —— 记进全局事实库（所有对话都看得见）。

「**高级**」里有参数（权重、半衰期、上限）、整理会话（补日期、补标「长期设定」、重判、查重、清洗补键）、
备份与导出、清空 —— 平时不用碰。删掉的记忆去顶部「**回收站**」找（能搜正文、能找回，也能彻底销毁）。

「清空」（1.10.2 起）分两种范围：**只清这个会话**（事实和工作区一行不动）和**全清**（事实 + 所有会话 + 工作区）。
不管哪种，清掉的都先进回收站，找回一条不少；真要毁掉，再去回收站点「把已删掉的清空」。
它会要你亲手打「清空」两个字才肯动手。

还有「**最近一次召回**」（在「会话」页签某个会话点进去）——
能看到这次问话它挑了哪几条、哪几条没挑上、为什么没挑上。

### 一条记忆哪来的：trace

问它「你怎么记得这个」「这条是啥时候记的」「为什么没想起来」，它会用 `trace` 翻给你看：

- 哪来的、什么时候记的、被强化过几次
- 有没有被标「已被取代」或「别记」
- 最近哪几轮被想起来（当时的相关度分数）

**只读**，不改任何东西。给记忆 id 最准；只记得片段就给几个词，它按时间挑最新那条。

## 一个列表看全、改全

记忆页顶部六个页签：**记忆**（全部记忆一张表）、**时间线**（按天看那天记了什么、又想起过什么，1.12.12 起）、
**会话**（会话列表 / 工作区记忆两个子页签）、**回收站**（删掉的记忆，能搜能找回）、**体检**（助手回复的 AI 味，1.10.0 起）、**高级**（参数、整理会话、导入导出、清空）。

**记忆**页签里，1.5.0 起不再分页签了 —— **一张列表就是全部记忆**，全局事实（所有会话共享，住 `_facts.json`）
和会话事件（只属于某个会话）在同一张表里，靠徽章区分：

- **所有会话** —— 哪个对话都看得见，改一处所有会话都按新的读
- **只在这个会话 · xxxxxxxx** —— 只留在那一个会话里

为什么并成一张表：事实不是某个会话的，以前塞在会话列表里，不点进某个会话就看不见全部；
而事件又只能在那个会话里看 —— 两边都得点进去，概念上对不上。

这张列表能做的事：

| 动作 | 怎么用 |
|---|---|
| 搜 | 顶上的框，搜正文、检索词、出处、「讲的是」都行 |
| 筛 | 作用域（全部 / 所有会话 / 只在这个会话）/ 类型 / 状态（活跃 / 已被取代 / 已删） |
| 改 | 点正文直接改，保存后所有会话都按新的读 |
| 删 | 点右边 × → 确认条问「所有会话都会忘」→ 确定才删 |
| 记 | 点「＋ 记一条」，写正文、选类型、给重要度 —— 记进全局事实库 |

> 删掉是**真删**（收进「已删」，不是销毁），但删完所有会话都不再记得这条。
> 想找回来，去顶部**回收站**页签：能按正文搜、能看清来源；确定不要了，还能在那里**彻底销毁**（会问两遍）。

## 体检：助手回复的 AI 味（1.10.0 起）

顶部「**体检**」页签，扫最近 N 天的助手回复，一条条标出 AI 味：

- 26 条词面规则（23 条正则 + 3 条跨条）：自贬开场 / 公式化反转 / 翻译腔 / 列表腔 / 讲课腔 / 硬接梗 /
  虚构现实行为 / 重复开场 / 连续同类回应 / 每条都带表情……
- 每条给证据和每百字得分
- 26 条规则**逐条开关**；关掉的记在 `<DSH_HOME>\clay-memory\reply-check-rules.json`
  （只存关掉的那些，新加的规则默认开着）
- **只观察，不阻断、不改写** —— 它不会替你改回复，也不会拦着不让发

## 如果你以前写过档案

很多人早就给自己的 AI 写过设定、记忆卡、日记。**不用重写**，导进来就行。

1. 设置页展开「**从旧档案导入**」
2. 选文件夹（或填路径）→ 点「**扫描档案**」
3. 它把档案拆成一条条候选，**列给你看**
4. 你勾掉不要的 → 点「**导入选中的**」
5. 再点「**开始提炼**」—— 它把这些原文改写成第一人称的记忆，顺手给每条出检索词、日期、重要度

> **提炼会调用模型**（走你 DSH 里的那个），一批几条、慢慢跑，可以随时停。
> 它会**从较新的内容往前做**，已经提炼过的不再重复。

**认得的格式**：`.md` `.markdown` `.txt` `.text` `.log` `.rst` `.org`
**子文件夹**会往下找两层。

## 参数（都能调）

**高级**页 → **参数**（默认收起成一行「▸ 参数 · 调一次就不动 · 点开调」，点开是一组旋钮）。
**每一项都有说明**，鼠标放上去能看到它在干什么。大致分三组：

| 组 | 管什么 |
|---|---|
| **权重** | 鲜活度 / 重要度 / 情绪各占多少分（四项合计 100%） |
| **时间** | 多久淡一半 |
| **门槛** | 命中多少才算相关、一次最多注入几条、每天最多记几条 |

两个跟「长期事实」有关的旋钮，默认都是关的（1.12.19 / 1.12.23 起）：

- **画像免证据名额**（`factsAlwaysTopN`，默认 0）：长期事实里排最前的 N 条**画像**，不看这句话问了什么、直接每轮带上。
  起因是真库里 62 条画像有 74% 死在证据门上（C=0），每轮只进 1.56 条。0 = 全都要有证据才进。
- **知识退出常驻**（`knowledgeStaysOut`，默认 0=关）：打开后技术笔记不再占常驻名额，只走「证据命中」那条路。
  实测代价实在（60 句技术问句里空注入从 6 句涨到 18 句），所以默认关、等观测。

**一个建议**：`证据门槛` 卡的是「证据」不是「鲜活度」，所以**调它不会误伤该想起来的**。
想让它更少说话就调高，想让它更容易想起来就调低。

## 分层记忆：事实全局、工作区共享、事件自己（1.4.0 起，1.8.37 补工作区层）

记忆分三层，**存在三个地方**：

| 层 | 存在哪 | 谁能看见 |
|---|---|---|
| **事实**（`category = stable_profile`：偏好、身份、约定） | `<DSH_HOME>\clay-memory\_facts.json` | **所有工作区、所有会话共用一份** |
| **工作区**（`category = workspace`：项目知识、决策、术语，1.8.37 起） | `<DSH_HOME>\clay-memory\_ws-<sha256(工作区路径)>.json` | **同一个工作区（同一个目录）下的所有会话** |
| **事件**（其余：今天发生的事、情绪、流水） | `<DSH_HOME>\clay-memory\<会话id>.json` | 只在这个会话里 |

几个直接后果：

- **在一个会话里说「我换工作了」，别的工作区里也记得** —— 不用再复制粘贴。
- **同一个工作区的会话共享项目记忆**：A 会话里定的项目决策，B 会话（同目录）能想起来；**别的目录想不起来**（各工作区互不相通）。工作区身份 = 规范化后的目录路径（盘符大写、`/` 分隔、大小写不敏感、不解析符号链接）。
- **删掉一条事实是所有会话一起忘**（还会收进「已删掉的」，能找回来）。设置页点「删」会多问一遍，批量删也会单独提醒。
- 设置页的计数是两笔：**「全局事实 N 条」** + **「本会话事件 M 条」**；**工作区条目**在「会话」页签的
  「工作区记忆」子页签里单独看（能删、能找回，1.8.42 起），会话页签下拉框的数字是两种口径：
  会话子页签=会话数、工作区记忆子页签=该工作区记忆条数。
- 「复制记忆到别的会话」现在是**复制事件**（事实本来就是共享的，不用复制）。
- 从旧版本升上来时，**旧事实不会自动搬进全局库** —— 跑一次迁移脚本（见下）。
- 升级前**先备份** `clay-memory` 整个目录（脚本自己也会备份一份再动）。

### 类型：稳定事实还是一次性事件（1.10.0 起）

以前「重要度」和「是不是长期事实」是绑在一起的：重要度高就被当成长期事实。现在拆成两件事：

- **重要度**：这条有多重要（0~1），管的是「该不该优先想起它」
- **类型**：这条活多久 —— `stable`（长期稳定：约定、关系、长期偏好，进全局事实库、不随时间淡忘）
  / `event`（一次性：今天发生的事，会淡忘）

模型记的时候自己判断；不填就按「长寿特征」的规则猜，猜不出来一律当 `event`（宁可当事件记，也不把随口一句当永久设定）。

> **重要 ≠ 稳定**：今天发生了件大事，它仍然是一次性事件。

### 骨架层：每轮都在的那几句（1.10.0 起）

事实层解决的是「该想起来的时候能想起来」，但有些东西**不能靠召回** —— 关系、说话风格、边界，每轮都得在场。

骨架放在 `<DSH_HOME>\clay-memory\_core.json`，每轮固定注入，**排在一切记忆前面，不占「最多注入几条」的名额**：

```json
{ "items": [ { "content": "……", "core": true }, { "content": "……" } ] }
```

- `core: true` 的最多取 2 条 → 渲染成 **【核心画像】**
- 其余 → **【长期背景】**
- 文件不存在 / JSON 坏了 → 当空骨架，不影响对话
- **骨架有自己的字数预算**（1.10.3 起）：默认 `注入字数上限 × 0.4`（800 → 320 字），按重要度从上往下塞，
  塞不下就整条跳过、不切半句；`core: true` 那两条**永远不丢**。以前骨架跟事实挤同一份预算，写长了会互相挤

⚠ 这是**你本地的数据**，不进插件包（不然发布出去的就是作者的骨架了）。

### 项目记忆：工作区上下文（1.10.0 起）

`remember` 多了一个可选参数 `项目分类`。填了它，这条就落**工作区层**（只在同一个目录下的会话里看得见），并且：

| 分类 | 行为 |
|---|---|
| `goal` 项目目标 / `stack` 技术栈 / `constraint` 架构约束 | **常驻注入**，放在「你记得的事」前面，最多 4 条（按 goal → stack → constraint 排） |
| `progress` 任务进度 / `decision` 决策 / `todo` 待办 | 不常驻，跟普通记忆一起走相关性召回 |

不填 = 普通记忆，行为跟以前一样。**项目私事别记成普通记忆** —— 普通的会跨工作区可见。

### 推测（inference）与「转正」（1.8.36 起）

- **推测**是插件对用户的**假设**（带证据、带置信度），不是事实。**它默认不注入** —— 不会混进每轮对话的记忆里，只有在显式检索（基准回放、调试接口）时才会出现，且措辞强制带「（推测）」前缀。
- **确认（confirm）**：只表示「采信」，仍按推测处理、仍不自动注入；**转正（promote）**：变成正式记忆类型（身份/关系/约定/偏好/经历），此后进入正常注入流程，转正时间与来源证据都会留档可追溯。
- 一条推测至少要有 **2 条有效证据**（引用库里真实存在的记忆 id）才允许创建；被引用的记忆删掉后，这条推测会标出「证据已失效」。
- 目前的确认/转正/驳回走接口管理（`/dsh-clay-memory/inference`），设置页入口是后续版本的事。

### 从 1.3.x 迁移事实

在插件目录里跑（**先看报告，什么都不写**）：

```bash
node tools/migrate-facts.mjs                 # dry-run：只报「能搬几条、跳过几条」
node tools/migrate-facts.mjs --apply         # 真搬：先整目录备份，再并进 _facts.json
node tools/migrate-facts.mjs --apply --purge # 搬完顺手把会话库里的旧副本删掉（默认不删）
```

- **幂等**：同一条事实按「归一化文本」去重，重跑只会报 0 条新增。
- **默认不删原库副本**：搬完会话库里那份还在（万一想退回 1.3.7，事实还读得到）。
- 搬完会在 `clay-memory\_facts.migration.json` 写个标记，之后再跑直接跳过（`--force` 可以重扫）。
- **回退**：把 `clay-memory-backup\<时间戳>\` 里的文件拷回 `clay-memory\`，删掉 `_facts.json` 和那个标记，换回 1.3.x。

## 人称

记忆里你自己是「我」，用户是「**她 / 他 / ta**」—— **默认 ta**，可以在设置页改。

改完之后：

- 以后新记的会按你设的写
- 已有的记忆里那个字也会跟着换
- 提炼旧档案时也按你设的来

**说名字本身的句子不会被换掉**（「我的名字叫某某」不会变成「我的名字叫我」）。

## 事实键（同一条事只留最新）

有些记忆记的是**会变的东西**，光看句子像不像判不出来：

- 「身高一米七」和「长胖到 55 公斤」几乎是两件事，词面上却很像
- 「拼团还没开」和「拼团开了」是同一件事的前后，词面上却不像

所以每条记忆可以带一个**事实键**，写「对象.方面」，像 `她.身高`、`约定.身边位置`。
**同一个键 = 同一件事** → 只留最新那条，旧的标成「已被取代」（不再被想起来，但东西留着、能撤销）。

键从三个地方来，都是顺手给的，不多花一次调用：

- 模型记的时候自己填（`remember` 的可选参数）
- 提炼旧档案时顺手出（第六格）
- 设置页的「**清洗补键**」按钮，给以前那些还没有键的旧条目补上

⚠ 键里**不许写具体的值** —— 写 `她.身高`，不写 `她.身高170`。
写了值就成了摘要：身高真变了，键也跟着变，两条永远碰不上。
**拿不准就留空**，留空完全没关系（留空只是享受不到这个便利，给错键却会埋掉一条正经记忆）。

清洗补键那一步是**后台活**：先「试 8 条看看」（一个字节都不写，只把键摆出来给你看），
确认了再真洗。跑完能一键「把补的键全摘掉」回到洗之前 —— 只摘自动补的，你自己填的键不动。

## 兼容性自检：DSH 换版之后，我还干不干活（1.12.78 起）

DSH 更新（尤其是预览版）有时会改事件名、动服务接口。**最坏的情况不是报错，是静默不干活** —— 插件不崩、日志不报错，只是「自动整理 / dream」这些事再也不发生。2026-11 那次 dream 静默失败三天就是这么来的。

所以体检页最上面多了一块「兼容性自检」，判断标准不是「有没有报错」，而是**「该发生的事最近发生过没有」**：

- **DSH 服务接口**：插件启动时要的那几个服务（给模型、工具、定时器、HTTP、会话）都拿到了吗
- **各条流水线**：记忆注入 / 自动整理 / 自动 dream / 经历提取，各自「上次成功」距今多久（先查日志，日志被轮转掉了就退到配置里的水位）
- **数据文件**：`_facts.json` / `_core.json` / `_stale.json` / 配置，都能读、结构都对吗

「跑一次自检」是浅检：零 token、毫秒级，点开页面就自动跑一遍。
「深度检查」会额外真的调一次模型，确认模型通路没断（这一步要花 token，所以单独一个按钮）。

诚实边界：事件改名没法当场发现（DSH 没把监听注册表暴露出来），最多两天能从「上次成功距今多久」看出来 —— 这个速度够用。

> 「工具拦截」1.12.79 起已停用：代码和测试留着，设置页里的「拦截」页签也撤了。
> 它原来做什么、怎么开回来，见 `docs/已停用功能-工具拦截与陈旧检查.md`。

## 它不做什么

- **不会自动删除记忆。** 淡忘只是越来越难想起来，内容一直在，设置页里看得到
- **不会把删掉的东西弄回来。** 删过的再导一次档案也不会复活
- **不会每个会话都强制用。** 默认开着，不想用的那间单独关掉；也能一键全关
- **不会替你写档案。** 它只把档案拆开、改写、存起来，写什么还是你的事

## 常见问题

**Q：会不会很占上下文？**
一次最多注入 6 条、加起来不超过 800 字（都能调）。超了的这次先进不来，下次可能就进了。
1.10.2 起每轮注入开头会带一行「**（这轮想起了 N 条）**」—— 数字就是这一轮真正用上的条数。

**Q：为什么它有时候想不起来？**
先看「最近一次召回」那张表 —— 它会写清楚哪条没进去、为什么。
常见原因：命中的词太普通（证据不够）、或者那条太旧淡下去了。

**Q：导入扫出来 0 条？**
它会告诉你为什么。常见的是：整篇是一大段话没分行、每行太短、或者内容都在表格/代码块里。

**Q：数据存在哪？**
`%USERPROFILE%\.dsh\clay-memory\` 里，分三层文件：`_facts.json`（全局事实）、
`_ws-<哈希>.json`（每个工作区一份）、`<会话id>.json`（每个会话一份）；
另有 `_core.json`（骨架层，每轮固定注入）、`reply-check-rules.json`（体检关掉的规则）。**纯文本 JSON**，你自己能打开看。
每次改动前它会自动备份一份。

**Q：装完包大了将近 900 KB？**
那里面是一份**通用中文词表**，用来分词。它只在本地当查找表用 ——
**不占上下文、不影响每轮对话的 token**，也不会因为你聊得多就变大。

**Q：记忆多了会不会越用越慢？**
不会。每次想起来的时候，它是把当前能看到的几百条**当场算一遍**再挑；
稀有度那张表在内存里按「库指纹」缓存（条数、字数、tags 一变就重算），**不落盘、不建持久表**。
在 850 条这个量级，冷启动一次建表约 60 ms，预热后每句 1~2 ms。
真要建持久表（`term_stat`）得在每次增删改时同步更新统计，一旦算错就会影响「什么该被想起来」——不如不建。
等哪天库真到几千上万条、现算成了瓶颈，再补这张表（记在需求文档的待办里）。

## 开发：改完页面怎么验

`lib/client.js` 是构建产物，改 `src/client/` 之后要重新打包：

```bash
npm run build:client
```

三条护栏（按顺序跑）：

1. **`npm test`** —— 其中 `tests/page-scope.test.mjs` 会扫每个页面模块，
   揪出「用了、但既没声明也没从参数/import 拿到」的名字。拆文件时漏传依赖，
   真机上那一页会整块白掉，而其余测试全绿，所以这条单独立着。
2. **`npm run check:client`** —— 校验仓库里的 `lib/client.js` 与 `src/` 的构建结果一致，
   防止「改了源码忘了打包」。
3. **`npm run ui-check -- <端口> <DSH_HOME>`** —— 真浏览器把页面点一遍：
   六个页签、高级页展开参数、会话详情展开记忆列表、记忆页点「改」，
   最后拦 `/list` 返回「一个会话都没有」，验一遍「空库引导卡」出不出来（不动真实数据）。
   它要活着的实例和 Chrome，所以不进 `npm test`，改页面后手动跑一次。
   要验后端也真为空的那条链路，加 `--empty`：把 `<DSH_HOME>/clay-memory` 临时改名、
   原地建个空目录跑一遍，跑完在 `finally` 里原样挪回（中途失败也会挪回）。

```bash
node tools/build-client.mjs
node tools/ui-check.mjs <实例调试端口> <该实例的 DSH_HOME>
node tools/ui-check.mjs <实例调试端口> <该实例的 DSH_HOME> --empty   # 顺带验真空库
```
